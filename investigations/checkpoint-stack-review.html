Partial-rollout checkpointing · NeMo Gym PRs 2939–2946

Checkpoint Stack Review

Stack tip 5b189df61 (fix: close participant integration gaps) Base pthombre/tokcap/full-stack Reviewed 2 September 2026 Scope lifecycle re-derivation and edge-case catalogue

The stack builds the right participants with the right fencing discipline, and the single-participant mechanics are sound. Admission close is atomic with the admission test, every control route is fenced by checkpoint id with idempotent replay, every commit writes payloads before its manifest, and every restore validates the whole set before activating anything.

The gaps are between participants, not inside them. Five need to close before NeMo RL integrates. A restored continuation re-tokenizes its whole conversation because parent resolution never looks across attempts, so pre-checkpoint generations train as prompt carry. The checkpoint taken after a restore drops every restored ledger, because admission tombstones double as commit exclusions. The agent and model checkpoint directories are not namespaced by instance, so with two agent servers the second commit silently returns the first server's manifest. The prepare order is safe only as agents, then resources, then policy model, and nothing in Gym enforces it while the whitebox agents turn either wrong order into a lost or corrupted boundary. And the controller cannot see which executions block a prepare, because neither the agent nor the resources participant exposes a status route. On the resources side three more break the participant for real environments: any identity-carrying request that fails before a session exists poisons every later prepare, every Gymnasium environment advertises state export that most of them cannot perform, and MCP tool traffic is refused outright.

What the stack implements

Eight PRs, each a dependent layer. The rows name the participant each layer adds and the routes it exposes. Every control route lives under /ng-control/v1, requires the bearer resolved from NEMO_GYM_CHECKPOINT_CONTROL_TOKEN (or the external-staging control variable), and carries a checkpoint_id plus an absolute deadline_ts.

The lifecycle as the code runs it

The figure follows one checkpoint across the five participants. Arrows are the actual routes. The numbers on the prepare arrows are the only safe order, derived from what the agents do when a call is refused; that order is argued in the edge cases below.

Runtime — every participant records what it already owns

/run · /v1/responses · tool routes · /verify

The actor posts /run with task index, rollout index and attempt index. The agent's /run wrapper establishes the execution identity from the body, registers the execution with the agent participant (one active run per attempt, closed admission or a tombstone gives HTTP 409), and installs the rollout context so every downstream call carries the two identity headers.

Each policy call reaches the model server through the admission middleware, which is outermost. It reads the identity from the headers, or from the /ng-rollout/<key>/ path when a client we do not control sent no headers, refuses tombstoned attempts, and counts the request in flight until the ASGI call returns. Inside, the capture middleware mints a model-call id, resolves the request's parent by fingerprinting the conversation against this capture key's ledger rows, hands the worker a token-in admission with the parent's staging chain, and after the worker's acknowledgement appends a token-free custody row. The model-call id is echoed on the response.

Each tool call reaches the resources server through the session middleware, which serializes mutations per attempt, refuses tombstoned attempts, and stamps a revision header on every successful response. The agent keeps the last revision it saw.

After every turn that made tool calls (SimpleAgent) or every nonterminal step (GymnasiumAgent), the agent commits an AgentBoundaryRecord: the output items so far, usage, the last model-call id, the resources revision, and agent-specific state including plain cookie values. When no checkpoint is in progress the commit returns immediately.

Divergence from the doc. The doc's runtime phase records nothing per rollout on the filesystem; the stack matches that. The doc also expects the agent to check a park flag before every operation; the stack parks only inside commit_boundary, so a run parks after its current turn completes, never before a model call.

Prepare — stop new work and reach a recoverable boundary

agent-checkpoint/prepare · resources-checkpoint/prepare · model-admission/pause, status, abort_inflight

Agents first. prepare closes /run admission, moves every running execution to park-requested, and waits until every execution is parked or finished, or the deadline passes. A parked execution is blocked inside commit_boundary with its HTTP request still open. At the deadline the route answers HTTP 409 agent_prepare_incomplete with a count, leaves admission closed, and the controller retires the stragglers by attempt and calls prepare again for the same checkpoint id.

Resources second. prepare closes mutation admission, then takes every registered session's lock in turn and exports it through the server's export_checkpoint_state hook, each with the remaining deadline. A request waiting behind a lock is re-checked after acquiring it and refused. A failure leaves admission closed.

Policy model last. pause closes admission and returns immediately with the drain state; status long-polls until nothing is in flight and marks the fence prepared. abort_inflight tombstones one attempt and cancels its in-flight requests; the request stays counted until its task exits and the capture middleware writes a failure row for the uncommitted call.

Divergence from the doc. The doc orders prepare as model drain first with agents parking on 409 checkpoint_parked. In the stack, neither whitebox agent treats that code as a park signal, so the model must be paused only after every agent is parked. The doc also specifies status long-poll routes for agents and resources; the stack has none, so the controller's only view of a stuck prepare is the failure count.

Save — commit each participant, then publish

agent-checkpoint/commit · resources-checkpoint/commit · model-checkpoint/commit

Each commit takes the controller's checkpoint directory. The agent participant writes one JSON file per parked execution under agent/; the resources participant writes one JSON file per exported session under resources/<server_name>/; the model participant copies one ledger file per non-tombstoned capture key under model-ledger/ and records every tombstone plus every attempt the server ever admitted as source_attempts. Every writer fsyncs payloads, then writes its manifest through a temporary name and rename, then fsyncs the directory. A repeated commit for the same checkpoint id validates the existing manifest and returns the original result, which covers a lost acknowledgement.

The model commit refuses unless admission is paused with zero in flight. The agent commit refuses while any execution is between boundaries. The TransferQueue snapshot and the final publication of training_info.json remain on the RL side.

Divergence from the doc. The doc requires streaming frozen state into compressed shards with a member index so the shared filesystem never receives one file per rollout. The stack writes one file per parked run, one per session, and one per capture key, each with its own fsync.

Restore and resume — fresh processes, paused, then opened in order

model-checkpoint/restore · resources-checkpoint/restore · agent-checkpoint/restore · */resume

The model restore closes admission first, refuses a capture directory that already holds ledger files, verifies every file's digest before copying any, and installs a tombstone for every attempt in the manifest's tombstone and source-attempt lists. The resources restore loads and verifies the whole snapshot set, calls restore_checkpoint_states once with every snapshot re-labelled attempt N+1, and only then tombstones the source attempts. The agent restore installs each boundary as the continuation for attempt N+1 and tombstones N. All three leave their fence in restored_paused.

Resume is explicit per participant and retires the checkpoint id on that server. Because a released parked run immediately calls the model and resources servers, the order is resources, then model, then agents. A continuation is dispatched as a normal /run whose attempt index is exactly the source attempt plus one; the agent finds the restored boundary by that pair, skips seeding or reset, and continues from the restored conversation.

Divergence from the doc. The doc verifies each selected continuation against the restored TransferQueue rows before dispatch and downgrades a rollout with a missing row to a fresh dispatch. The stack has no such reconciliation, and, as the next section shows, the continuation would not chain to those rows even if they were present.

Edge cases to guard against

Each entry names the failing sequence, the consequence, whether the stack guards it today, and the guard that would close it. Severity reflects the effect on training data or on the checkpoint completing, not on code size.

Identity and fencing

E1 Rollout ids reused after a restart are fenced forever serious

Sequence

The model restore installs a tombstone for every attempt the old process had ever admitted (ledger.py writes source_attempts from AdmissionLimiter.seen_attempts(); restore calls install_tombstone for each). After the restart the dispatcher assigns a new task the same {task}-{rollout} indices a pre-checkpoint rollout used, at attempt 0.

Effect
Every policy call of the new rollout is refused with HTTP 409 stale_attempt. The rollout fails without ever generating.
Stack today
not guarded
The identity docstring warns that reused indices repeat a capture key, but nothing enforces uniqueness across the restart boundary.
Guard
NeMo RL must pass an explicit _ng_rollout_id that is unique for the whole job (a step or epoch prefix), and Gym should reject a dispatch whose attempt 0 collides with a restored source attempt with a distinct error code rather than the stale-attempt code.

E2 Explicit ids that end in -aN split wrongly for header-less callers minor

Sequence
A blackbox harness reaches the model server through its base URL only, so identity comes from the path. An explicit logical id such as run-a1 at attempt 0 produces the capture key run-a1; the path splitter reads it as rollout run, attempt 1, while the agent's header-carrying calls say run-a1, attempt 0.
Effect
The tombstone written for the agent's identity never matches the harness's calls, so a sacrificed blackbox attempt is not fenced at the model server.
Stack today
not guarded
Only index-derived ids are safe.
Guard
Reject explicit rollout ids matching .*-a\d+$ at dispatch, or make the attempt suffix unambiguous (for example ~a1, a character the id grammar forbids).

E3 Calls that carry no identity are admitted but can never be sacrificed serious

Sequence
A blackbox harness whose base URL carries no capture prefix (token capture off) sends neither headers nor a keyed path. The model server admits the call with an empty identity; abort_inflight matches tickets by identity only. On the agent side, a /run body without task and rollout indices bypasses the participant entirely: the run is never registered, cannot be parked, and prepare reports success over it.
Effect
One long identity-less generation holds the model drain to the deadline with nothing the controller can target; untracked runs keep issuing calls through a checkpoint the controller believes is quiescent.
Stack today
not guarded
Guard
When checkpoint control is enabled, refuse gated routes and /run without identity, and add an abort form addressed by ticket id for anything that still slips through.

Prepare order and the deadline

E4 The only safe prepare order is agents, then resources, then policy model blocker

Sequence

Model paused first. A whitebox run that is mid-turn issues its next policy call, receives HTTP 409 checkpoint_parked, and raise_for_status raises. The /run wrapper records the execution as failed; only parked executions are committed, so the boundary the run committed one turn earlier is discarded and the run's HTTP call returns an error to the actor.

The prepare then reports zero running executions and succeeds, so the loss is invisible: the report carries no count of executions that failed after park was requested. GymnasiumAgent additionally closes its environment on the way out.

Resources prepared while agents are still finishing a turn. SimpleAgent does not call raise_for_status on tool responses; it reads the HTTP 409 body as the tool output string, appends it to the conversation, and commits a boundary containing that text; the code comment there says resource-server errors are valid model-visible tool outputs. The continuation resumes with a checkpoint error inside its history, and the boundary's recorded revision is stale because a refused call carries no revision header. GymnasiumAgent raises on the refused /step instead, so its run fails and closes the environment. A run on its terminal turn needs /verify, which the resources middleware also treats as a mutation, so it is refused and the finished rollout is lost.

Effect
Model-first loses continuations that had valid boundaries. Resources-first corrupts the boundaries that do get committed and the token rows generated from them afterwards.
Stack today
not guarded
The order is not enforced or stated; PR 2942's body describes parking in isolation.
Guard
Document the order as a contract of the NemoGym actor; make the whitebox agents treat checkpoint_parked and resources_admission_closed as park-now signals that commit the boundary reached so far instead of failing; and make tool-call responses with HTTP 409 checkpoint codes never enter the conversation.

E5 The controller cannot see which executions block a prepare blocker

Sequence
Agent prepare times out and answers HTTP 409 with a count of running executions. AgentCheckpointParticipant.status() lists each execution's rollout, attempt, state and boundary index, but no route exposes it. The resources participant likewise has an unexposed status().
Effect
To apply deadline_policy: restart_safe_rollouts the actor must retire exactly the executions that are between boundaries. It can only retire everything it dispatched, which also discards parked continuations, or retire nothing and abort the checkpoint.
Stack today
missing
The doc's agent/status long-poll with parked | running | mid_operation is not implemented.
Guard
Add GET agent-checkpoint/status and GET resources-checkpoint/status (fenced, long-poll optional) returning per-execution state, and include the blocking attempts in the prepare-incomplete error body.

E6 Judge and simulator instances default to the policy role serious

Sequence
BaseResponsesAPIModelConfig.instance_role defaults to policy. A judge model configured as a separate instance advertises instance_role: policy in its capabilities and installs the admission middleware. The actor pauses every policy instance.
Effect
A verifier's judge call during the drain is parked. The judge fail-safe turns that refusal into a completed verification with reward 0.0 and a failure class, so every rollout that reaches its terminal turn during the pause is scored zero without an error, and because that response is a success the session is retired, leaving nothing to re-verify. A verify that is still waiting on the judge holds its session lock, and the resources prepare waits on that lock until its deadline.
Stack today
config footgun
The role is a per-instance config field with the unsafe default.
Guard
Default to auxiliary and let the training config mark the one instance NeMo RL generates through as policy, or validate at startup that exactly one policy instance exists per training run.

E7 Blackbox agents advertise boundary support they cannot deliver serious

Sequence
Every agent server inherits the same /run wrapper and the same capability declaration (checkpoint_mode: export_restore whenever a bearer is configured). A Claude Code or OpenCode run registers an execution but never commits a boundary.
Effect
Agent prepare on a blackbox agent always waits to the deadline and fails. The actor cannot tell from capabilities that these executions should be retired immediately as restart-only.
Stack today
not guarded
Guard
Make checkpoint_mode a per-agent-class declaration (blackbox agents report stateless), and have prepare on a stateless agent return immediately with its executions listed for retirement.

E8 Abandoning a checkpoint must reopen every participant explicitly minor

Sequence
Agent or resources prepare fails at the deadline; both leave admission closed while the fence returns to idle. The controller decides to abort the checkpoint instead of retrying.
Effect
Without a resume call the server refuses all new work indefinitely. The single-worker model pause cannot fail, and the coordinator pause reopens itself on failure, so the asymmetry is easy to miss.
Stack today
guarded
Both resume routes accept the idle phase, so the abort path exists; it is just not automatic.
Guard
The actor's abort_checkpoint must call resume on every participant it prepared, including the ones whose prepare failed.

E9 Retired executions leave orphan sessions in the checkpoint minor

Sequence
The controller retires an execution that missed the agent deadline. The resources participant still exports that attempt's session at prepare, and restore installs it under attempt N+1, but no continuation will ever dispatch that attempt.
Effect

Memory and checkpoint bytes accumulate across checkpoints for sessions nobody can reach. Retire itself touches only the agent participant: the model needs its own abort_inflight for the same attempt or the attempt's ledger rows are committed as trainable, and the resources participant has no per-attempt retire at all.

The fresh re-dispatch of a sacrificed rollout must also use attempt N+1, because attempt N is refused everywhere after restore. That fresh run then overwrites the adapter's mapping for N+1, the restored session leaks, and its first mutation reports the restored revision plus one for state the run never saw.

Stack today
not guarded
The doc's resources/retire {rollout_id, attempt} route is not implemented.
Guard
Add the resources retire route; define sacrifice as agent retire, then model abort, then resources retire for the same attempt, before any commit; and have resources prepare export only sessions whose attempt has a committed agent boundary.

The token chain across the attempt boundary

E10 A restored continuation re-tokenizes its whole conversation blocker

Sequence

Attempt 0 of rollout 4-2 made three policy calls; their custody rows live in 4-2.lineage.jsonl and their token deltas in TransferQueue. The checkpoint commits that ledger and the agent boundary whose last_committed_model_call_id is the third call. After the restart the continuation runs as attempt 1 with capture key 4-2-a1. Its first policy call sends the full conversation. resolve_parent asks the lineage store for the parent under context.rollout_id, which is 4-2-a1; that key has no rows, so the external-staging admission falls to the text root branch and the worker re-tokenizes the entire prompt.

Effect
The three pre-checkpoint generations enter the continuation's staged row as prompt carry with mask 0. The terminal chain RL linearizes contains no policy-generated tokens from before the checkpoint, and the attempt-0 chain has no terminal of its own. The rollout trains on a fraction of what the policy produced, silently. There is also no token-in link RL could use to stitch the two chains.
Stack today
missing
resolve_parent and FileLineageStore._resolve_row are scoped to one capture key; no request header lets the agent hand over the parent call id it holds, and nothing in the stack reads last_committed_model_call_id except the tests. The model restore also tombstones every source attempt, so the old key could not be reused legitimately even by hand.
Guard
Two workable designs. Either the model server resolves parents across attempts of one logical rollout (search the restored source-attempt ledgers named in the manifest for the fingerprint) and admits a token-in child whose staging_chain spans both attempts; or the agent sends x-nemo-gym-parent-call-id plus the source capture key on the first post-restore call and the model server verifies the fingerprint against that row before admitting. Either way the reconciliation step must confirm the parent's staged rows exist before the continuation is made runnable.

E11 The checkpoint taken after a restore drops every restored ledger blocker

Sequence
Restore installs a tombstone for every source attempt so late calls are fenced. Commit excludes every tombstoned capture key from the ledger copy, because the same set serves as the list of attempts force-closed at the deadline. The next checkpoint after a restore therefore skips every ledger file the restore installed: a probe that commits, restores on a fresh server, resumes, pauses and commits again gets zero rollouts and one exclusion, and the second checkpoint holds only a manifest.
Effect
A rollout whose life spans two checkpoints loses its pre-checkpoint custody after the second one. A later restore has no custody rows for the staged rows attempt 0 produced, and the continuation chain in E10 could not be stitched even after the lookup exists.
Stack today
not guarded
Confirmed by running the sequence.
Guard
Keep two sets: attempts fenced for admission, and attempts force-closed at this checkpoint's deadline. Exclude only the second from the copy; restored source attempts are fenced but committed.

E12 Custody and staged rows are never reconciled after restore serious

Sequence
TransferQueue's memory-resident rows survive only through its own checkpoint cut. If the cut and the Gym commit disagree (a torn cut, a retried save, an operator restoring one from an older checkpoint), custody rows reference staging keys that no longer exist.
Effect
Nothing on the Gym side checks. A continuation whose parent chain is missing fails only at its next policy call, when the worker cannot fetch the prefix, and a completed rollout with missing rows fails only when RL linearizes it.
Stack today
RL-side, absent
The manifest route (/training-token-capture/control/rollouts/{key}/manifest) provides the staging keys and chain hashes to reconcile against; a continued rollout's chain sits under two capture keys.
Guard
Implement the reconciliation in the actor before dispatch: for every restored capture key, every manifest row's staging key must exist with a matching digest, or that logical rollout downgrades to a fresh dispatch.

E13 Aborted calls leave orphan staged rows and failure rows guarded

Sequence
abort_inflight cancels the model server's task while the worker has already staged the delta durably. The capture middleware's cleanup writes a failure row for the uncommitted call; the staged row stays in TransferQueue.
Effect
The attempt is tombstoned, commit excludes its ledger by capture key, and the staged row is an orphan that normal cleanup removes. Failure rows carry no fingerprint so they can never be chosen as a parent.
Stack today
guarded
Consistent with the design's masked-orphan rule; the tombstone keys and ledger file names agree for attempt 0 and attempt N through capture_key_for. Two loose ends: a cancellation that lands while the custody row is being written leaves both a custody row and a failure row for the same call, and the cancelled client receives an opaque HTTP 500 rather than a 409, so an agent records it as a failure instead of a park.

E14 Model restore needs an empty capture directory minor

Sequence
A model server restarts on the same node with the same capture directory. Restore finds ledger files not named in the manifest and refuses.
Effect
Restore fails until an operator clears or repoints the directory; token JSONL and lock files in the directory are not inspected at all.
Stack today
fails closed
The refusal is correct; the operational requirement is unstated.
Guard
Accept a directory whose existing files are a subset of the manifest with matching digests, so a same-node restart and a retried restore both succeed; otherwise provision a fresh, checkpoint-id-suffixed capture directory per restart and state it in the deployment docs. Nothing ever deletes a ledger file today.

E15 The model-call id is echoed only on capture-prefixed calls minor

Sequence
The capture middleware appends x-nemo-gym-model-call-id only when the request path carried a capture key, and never on an exception-path HTTP 500. An agent that identifies calls by headers alone, with capture disabled, reads no header.
Effect
Every boundary records last_committed_model_call_id as null, which removes the only join key the reconciliation in E12 could use.
Guard
Mint and echo the id whenever admission resolved an identity, not only when a capture prefix is present.

Agent continuation

E16 The continuation's attempt index must be exactly source plus one serious

Sequence
The agent restore stores the boundary under (rollout_id, attempt + 1) and the resources restore installs sessions under the same pair. The dispatcher, which also increments the attempt on ordinary retries, sends the continuation with attempt N+2.
Effect
checkpoint_continuation finds nothing and the run silently starts fresh: it seeds a new session, ignores the restored one, and generates from the original input under an identity that the resources server has no state for.
Stack today
not guarded
A miss is indistinguishable from a fresh dispatch.
Guard
Have the actor read the restore result (source attempts) and dispatch continuations with exactly N+1; have the agent refuse a fresh dispatch for a logical rollout that holds an unconsumed continuation.

E17 A parked run holds its HTTP connections for the whole checkpoint serious

Sequence
A parked SimpleAgent run has two open requests: the actor's /run and the agent's self-call to /v1/responses. Gym's own aiohttp client is built with ClientTimeout(), so it never times out, and internal requests retry forever on transport errors. The actor's client is RL's choice.
Effect
If the actor's client times out and retries /run while the original is still running, the retry is refused with duplicate_execution and the original completes onto a socket nobody reads; the result is lost. If the retry arrives after the original completed, begin accepts a second execution under the same attempt: it seeds a new session and appends new ledger rows under the same capture key with nothing to deduplicate them. If a connection drops during a same-process resume, the self-call is retried and runs the episode a second time from the seeded session.
Stack today
not guarded
There is no result-handoff acknowledgement or registry on the Gym side, as the doc assumes on the RL side.
Guard
The actor must issue /run with no total timeout and treat duplicate_execution as "still running". On the Gym side, cache each attempt's terminal result and return it to a duplicate dispatch, which is the smallest form of the doc's transferred-to-RL handoff.

E18 Completed executions are never released from memory serious

Sequence
AgentCheckpointParticipant.finish marks an execution completed but leaves it in _executions with its last boundary record, which holds the full conversation. _restored keeps every installed continuation after it is consumed.
Effect
Agent-server memory grows with every rollout attempt ever run in the process, multiplied by conversation size; a 5,000-run check holds all 5,000 records with their conversations, and status() rescans every entry on each prepare wake-up. At tens of thousands of rollouts per step this is gigabytes per day.
Stack today
not guarded
Guard
Drop completed and retired executions when the actor acknowledges their result, or at least drop their boundary payloads on finish.

E19 Retire cancels the wrong task, and a retired loop can corrupt its successor serious

Sequence

The /run wrapper registers the /run task with the execution, but SimpleAgent's loop runs inside its own self-call to /v1/responses, and that inner handler is where commit_boundary parks. retire sets the resume event and cancels the outer task only. The inner loop wakes in the retired state and keeps generating; a repro shows it committing two further boundaries after retirement. The model server fences the attempt only if the controller also called abort_inflight for it.

begin then accepts a new execution under the retired key and replaces the dictionary entry. The stale loop's next commit_boundary lands on the new execution's record, and the new run's own first boundary is refused because its index does not increase.

Effect
A sacrificed rollout keeps consuming policy generations, and a later legitimate run under the same attempt inherits a boundary it never produced.
Stack today
not guarded
Guard
Register the task that actually calls commit_boundary (or cancel through a per-execution scope both handlers share); refuse begin while a retired execution's loop is still live, for example with a generation counter on the execution; and pair every agent retire with a model abort_inflight for the same attempt.

E20 Park requests outlive an abandoned checkpoint serious

Sequence

Prepare marks every running execution park-requested and closes admission. It times out; the fence rolls back to idle, but the participant stays closed and the executions stay park-requested. The controller abandons the checkpoint and calls resume. Resume reopens admission and releases executions that are already parked, but leaves park-requested ones as they are; at their next boundary they park and wait for a resume that never comes.

Resume also marks a parked execution whose task was cancelled as retired without setting its event, so a SimpleAgent inner handler in that state waits forever. After a same-process checkpoint that execution's boundary is in the checkpoint but there is no in-process continuation, so a re-dispatch at N+1 starts from scratch while the resources server still holds attempt N.

Effect
After any aborted or retried checkpoint, runs that were mid-turn at the time hang at their next boundary with no active checkpoint, and their /run calls never return.
Stack today
not guarded
A repro shows an execution parked with the participant reporting accepting.
Guard
Resume resets park-requested executions to running and releases or cancels task-less parked ones; a failed prepare undoes its own marks before returning the error.

E21 A boundary committed at max_steps breaks the continuation serious

Sequence

GymnasiumAgent commits a boundary after every nonterminal step, including the last one allowed by max_steps. After a restart the continuation's loop range is empty, no model call is made, and the code then reads last_model_response.output on a value that is still None.

SimpleAgent commits its boundary before the max_steps check, so a run parked at the last step continues after restore with one more model call than the configuration allows.

Effect
The Gymnasium continuation fails with an attribute error and the rollout is lost after the restart; the SimpleAgent continuation exceeds its step budget.
Stack today
not guarded
The existing Gymnasium continuation test passes only because its environment terminates on the first continued step.
Guard
Never commit a boundary when the step equals max_steps; a continuation whose boundary index already meets the budget returns the truncated response built from the restored items.

Resources state

E22 Header-less callers are refused on every path, including liveness blocker

Sequence
ResourcesSessionMiddleware is installed outermost on checkpoint-enabled resources servers and treats every path outside /ng-control/, /aggregate_metrics and /reverify_mode as a mutation that requires both identity headers. Callers without them: the liveness probe GET / that run_webserver installs on every server, MCP tool calls from sandboxed harnesses (the Claude Code and Codex harnesses send only X-NeMo-Gym-Session-Token), re-verification's direct /verify when observability is off, external /run callers that omit the task and rollout indices, and OpenAPI or docs requests.
Effect
Every MCP tool call on Gymnasium, Workplace Assistant or the counter example fails with HTTP 409, re-verification cannot run against these servers, and any health probe that checks the status code marks the server down (gym env status itself ignores the code, so it still reports success).
Stack today
not guarded
Guard
Scope the middleware to POST mutation routes; exempt /mcp and resolve its identity from the signed session token by minting the rollout and attempt into it at seed time, then lock and count revisions inside the tool dispatch; derive identity for /verify from the body regardless of observability, or treat a verify on an unknown key as stateless.

E23 The capture-path prefix defeats the terminal-session check serious

Sequence
The session middleware runs outside RolloutContextMiddleware, so it sees the raw path and compares it to /verify literally. With observability on, every resources call from an agent arrives as /ng-rollout/<key>/verify. The verify succeeds, but the middleware never retires the session.
Effect
Every completed rollout's session stays registered, is exported at every prepare, and is reinstalled under attempt N+1 at every restore, forever; a run confirmed the counter example never frees its sessions. Workplace Assistant and Gymnasium survive only because their adapters mark the terminal themselves. A prefixed request that carries no headers is also refused before the context middleware could read the identity from the path.
Stack today
not guarded
Guard
Strip the prefix before classifying the path, or install the session middleware inside the context middleware and read identity from the context variables.

E24 Agent revisions and resources revisions are never compared serious

Sequence

The agent boundary records the last revision header it saw; the resources snapshot records state_revision at export. A tool call that mutated state but returned an error (no revision bump), or a turn that finished after the last boundary but before the agent parked, leaves the two numbers apart. record_mutation also bumps the revision on reads and on /seed_session.

Prepare itself makes the comparison unreliable: it materializes the list of sessions and their revisions before taking each lock. A mutation still in flight at that moment completes, bumps the revision to 2, and returns the header 2 to the agent; the export runs afterwards on the mutated state but the snapshot is stamped 1.

Effect
A continuation can resume against environment state one or more mutations ahead of the conversation it remembers, and nothing flags it. A controller that does compare would see a false mismatch on every session that had a mutation in flight at prepare.
Stack today
RL-side, absent
PR 2943 defers the comparison to the controller.
Guard
Read the revision after the lock is held, not from the pre-materialized list; bump it only on routes that mutate; and have the actor compare the boundary's revision per server with the snapshot's before dispatching a continuation, downgrading any mismatch to a fresh dispatch.

E25 Any identity-carrying request that fails before a session exists poisons every later prepare blocker

Sequence
The middleware registers a revision for the identity before the handler runs; the adapters map the identity to a session only when seeding or reset succeeds; and export indexes that mapping without a guard. A /seed_session with a bad body (HTTP 422), a tool call before seeding (HTTP 200 on a fresh cookie session), or a Blackjack /step before /reset (HTTP 500) each leaves a registered key with no mapping.
Effect
The next prepare raises KeyError on that key, fails, and leaves admission closed. No route can clear the key, so every later checkpoint on that server fails until the process restarts. A run confirmed all three triggers.
Stack today
not guarded
Guard
Register only on the first successful response, and make export_checkpoint_state skip and report keys it cannot map instead of raising.

E26 A verify or terminal step in flight at prepare makes the prepare fail serious

Sequence
Prepare snapshots the session list, then waits for each session's lock. A /verify holding a lock completes, the adapter drops the session and the middleware retires the key; prepare then acquires the lock and exports a session that no longer exists.
Effect
KeyError, prepare fails, admission stays closed. A run confirmed it with one verify in flight.
Guard
After acquiring each lock, re-read the registry and skip keys retired in the meantime.

E27 A fresh process accepts continuation traffic before its restore serious

Sequence
The participant starts accepting; restore is what closes admission. A continuation's tool call for attempt N+1 that reaches the server before the restore succeeds on a cookie-bound session. Restore then maps N+1 to the restored session.
Effect
The early mutation is orphaned on a session nobody can reach while the model has already seen its tool result; after resume the continuation reads the restored value. A run confirmed the divergence.
Guard
Refuse an attempt above zero that has no mapping unless a restore has run, or start paused whenever a restore directory is configured, and have the actor dispatch nothing before every restore has returned.

E28 Every Gymnasium environment advertises state export that most cannot perform blocker

Sequence
The Gymnasium base enables checkpoint state for every subclass and exports session_state[session_id]. Sokoban, Tetris and TALES keep live environment objects in a different dictionary; the multi-turn example keeps session_turns; OpenAir stores a backend episode id that a fresh process cannot reuse. Only Blackjack keeps JSON-safe state where the base looks.
Effect
The controller sees export_restore, calls prepare, and the first live session raises, closing admission; for OpenAir the export succeeds and the restored state fails on its next step. A run confirmed the multi-turn example fails at export.
Guard
Default checkpoint_state_enabled to false in the Gymnasium base and opt in per subclass, or gate it on the subclass overriding the serialization hooks.

E29 Serialization changes value types on the way through a checkpoint minor

Sequence
The Gymnasium base round-trips state through JSON, so tuples come back as lists, and NumPy scalars or sets fail at prepare. Workplace Assistant's DataFrames come back with None as NaN and a plain index in place of a range index.
Effect
Verification cannot diverge (the verifier never reads the frames, and over HTTP both serialize as null), but tool code that branches on is None behaves differently after a restore. Blackjack's random-number state round-trips exactly. The adapter tests skip the JSON hop, so they would not catch a regression.
Guard
Normalize NaN back to None and reset the index on restore; add the serialize-to-JSON hop to the adapter tests.

E30 Non-adapted stateful environments must be treated as restart-only minor

Sequence
A stateful resources server that has not implemented the export hook advertises checkpoint_mode: stateless. After a restart its sessions are gone while the agent continuation still carries the old cookie.
Effect
If the actor continues such a rollout anyway, the server silently creates fresh state under the old cookie's session id and the continuation runs against an empty environment.
Stack today
declared
The capability is honest; the actor must honor it by restarting those rollouts from input.

Control plane and operations

E31 Agent and model checkpoint directories are shared by every instance blocker

Sequence
The resources participant writes under resources/<server_name>/. The agent participant writes under agent/ and the model participant under model-ledger/, with no server name. Both return the existing manifest when one is already present. A training run with two agent servers, or two policy model instances, gives every participant the same checkpoint directory.
Effect
The second agent server's commit validates the first server's manifest, reports its digest, and never writes its own records; restore on the second server installs the first server's continuations. A probe with two agent servers confirmed it. The same holds for two policy model instances.
Stack today
not guarded
The PR bodies describe one controller-provided directory.
Guard
Namespace every participant's subdirectory by config.name, as the resources participant already does, and record the name in the manifest so a restore on the wrong instance is refused.

E32 A failed model restore parks the server with no way to reopen it serious

Sequence
The model restore closes admission before it validates the checkpoint directory. Against a torn directory the validation raises, the fence returns to idle, and the limiter stays paused. Resume is allowed only from a non-idle phase.
Effect
Every generation request is parked until the process is restarted; a probe confirms resume answers invalid_phase for any checkpoint id. The coordinator has the mirror image: its resume broadcasts accepting before awaiting acknowledgements, and a missing worker leaves the fence prepared while every worker is already open.
Guard
Validate first and close admission last, reopen on any failure, and let resume from idle succeed whenever the limiter is closed.

E33 Status is refused after commit and restore, and commit needs a status poll first minor

Sequence
The model status route accepts only the preparing and prepared phases, so after commit or restore the controller cannot read tombstones or in-flight counts. The fence reaches prepared only when a pause or status call observes the drained state; commit requires prepared even though its own quiescence check would pass.
Effect
A controller that calls commit as soon as its own bookkeeping says the drain finished receives invalid_phase. After restore, the installed fences are unobservable until resume.
Guard
Allow status in every non-idle phase and let commit promote preparing to prepared when it finds the server quiescent.

E34 A commit retry after a torn publication ignores new tombstones minor

Sequence
The ledger commit renames its manifest and then fsyncs the directory; if the fsync raises, the fence returns to prepared with no recorded result. The controller aborts a straggler, which is allowed in prepared, and retries the commit. The retry finds the manifest and validates it as-is.
Effect
The published manifest omits the new tombstone, so restore never fences the aborted attempt.
Guard
On retry, compare the manifest's tombstones with the limiter's and rewrite the commit when they differ.

E35 A multi-worker drain that never reaches zero cannot be aborted or resumed serious

Sequence
The coordinator's pause returns after every worker acknowledges the closed state; the fence stays in preparing until status observes zero in flight. The coordinator's abort_inflight and resume accept only prepared and later phases. One worker holds a stuck generation.
Effect
The controller can neither tombstone the straggler nor reopen admission; the fence is stuck until the process restarts. The single-worker routes accept preparing, so the two implementations of the same contract diverge.
Stack today
not guarded
Production startup does not launch the coordinator yet, so the exposure is latent. The protocol also needs hardening before it is wired: a write to a half-closed worker socket raises a broken-pipe error the coordinator does not catch, a worker whose listener hits end-of-file never reconnects (a coordinator restart leaves the pool permanently missing, and a worker left draining parks all traffic), and re-registration by pid keeps dead worker records forever.
Guard
Align the coordinator's allowed phases with the single-worker routes; catch connection errors and reconnect with backoff; drop disconnected records on re-register; add a contract test that runs the same control script against both implementations.

E36 The two status routes have different signatures minor

Sequence
The single-worker model-admission/status requires deadline_ts as a query parameter; the coordinator's does not accept it as required and ignores the deadline for its wait.
Effect
A controller written against one deployment receives HTTP 422 or an unbounded long-poll against the other.
Guard
One shared request model for status, as the pause and resume routes already have.

E37 Agents and resources servers have no multi-worker story at all serious

Sequence
The agent and resources participants keep executions, sessions, locks and tombstones in process memory. With num_workers > 1, prepare on one worker parks that worker's runs only, commit exports that worker's sessions only, and a tombstone installed on one worker does not fence the others.
Effect
A checkpoint through a multi-worker agent or resources server is silently partial. The model server is no better today: its admission and checkpoint routes are installed on every worker regardless of the worker count, so a pause reaches one worker while the others keep appending to the shared ledger files during the copy, producing torn content under valid digests. Capabilities do report multi_process: unmanaged, so the actor can refuse it, and nothing else does.
Stack today
declared
Refusal depends on the actor reading capabilities before the first checkpoint.
Guard
Refuse to install checkpoint routes server-side when num_workers > 1 and no coordinator is attached, fail setup in the actor when any participant reports unmanaged, and extend the coordinator pattern to agents and resources before allowing more than one worker.

E38 Control routes appear only when the bearer is present in every process minor

Sequence
Each server installs its checkpoint routes only if NEMO_GYM_CHECKPOINT_CONTROL_TOKEN or the external-staging control variable resolves in its own environment. gym env start copies the launcher's environment into every server process, but servers launched by NeMo RL depend on RL setting the variable.
Effect
A server without the variable advertises checkpoint_mode: stateless and no admission states, which is honest, but a training run that expected continuation gets restart-only behavior without an error. There are also two bearer sources with a fallback chain, so a host that sets only the capture variable accepts a different token from one that sets the checkpoint variable, and control calls fail with HTTP 401 on some servers. The token cannot come from the run config; servers launched by NeMo RL need it in the Ray runtime environment.
Guard
Use one variable name for all checkpoint control routes, log the resolved source at startup, and have the actor assert the expected capability per participant and fail loudly on a mismatch.

E39 Restore is accepted at any time and adds to live state minor

Sequence
Each restore route is allowed from the idle phase whenever no checkpoint is active. Issued against a process that is already serving, the agent restore closes admission and installs tombstones without touching in-flight executions; the model restore refuses only when ledger files are present.
Effect
A misdirected restore silently freezes a healthy server until someone resumes it. On a resources server that prepared the same checkpoint, restore leaves the source attempt registered beside the replacement, so the next prepare exports both and the next restore installs three.
Guard
Accept restore only while the process has served nothing (a startup flag), and report the refusal with its own error code.

E40 Absolute deadlines assume synchronized clocks minor

Sequence
Every control request carries an epoch-seconds deadline; each server computes the remaining budget from its own clock.
Effect
A server whose clock runs ahead drains for less time than the controller intended; one that runs behind can outlive the controller's budget. Skew in cluster NTP is usually small, but a badly configured node makes prepare fail every time. The coordinator's abort and resume waits ignore the deadline entirely and use a fixed acknowledgement timeout.
Guard
Record the server's own clock in every control response so the controller can detect skew, and refuse a deadline that is already in the past by more than a small tolerance with a distinct error.

Scale

E41 One file per rollout on the shared filesystem serious

Sequence
Commit writes one fsynced JSON per parked execution, one per exported session per resources server, and one copied ledger per capture key, followed by directory fsyncs. Restore reads and copies all of them again.
Effect

Per rollout a commit costs about nineteen metadata operations and four full file reads across the three participants, and a restore about nine more. At tens of thousands of live executions that is millions of operations on Lustre per checkpoint, which is the pattern the doc's requirement on archive shards exists to avoid.

The model commit is worse than linear in live rollouts: it copies every ledger file in the store root, and nothing ever prunes that root, so each checkpoint re-copies the custody of every rollout the process has served since it started.

Stack today
not guarded
Guard
Introduce the shared checkpoint writer (compressed shards with a member index) and have all three participants stream through it; the manifest-last and digest discipline carries over unchanged. Commit ledger files incrementally by chaining manifests, and retire ledger files once the framework acknowledges the rollout's receipt.

E42 Fence and limiter bookkeeping grows without bound minor

Sequence
AdmissionLimiter._seen_attempts and _tombstones, ResourcesCheckpointParticipant._locks, the coordinator's tombstone list (re-broadcast in full on every state change), and the fence's retired-id map all only grow.
Effect
Memory grows with rollouts served: a run of 100,000 register-and-retire cycles leaves 100,000 locks and about 25 MB behind, and a restore of the same size adds 100,000 tombstones. The model manifest's source_attempts grows with every rollout the process ever admitted, and the coordinator's broadcasts become proportional to the tombstone count.
Guard
Retire bookkeeping when the actor acknowledges a rollout's result; carry into a checkpoint only tombstones for attempts that could still have a live caller.

What NeMo RL's actor must guarantee for this stack to be safe

  1. Assign rollout ids that are unique for the whole job and never end in -a<digits>; increment the attempt on every retry and dispatch continuations with exactly the source attempt plus one.
  2. Read every participant's capabilities at startup; refuse any that reports multi_process: unmanaged or a checkpoint mode weaker than the run expects; set the control bearer in every Gym server's Ray runtime environment.
  3. Give every participant instance its own checkpoint directory until the agent and model participants namespace by server name.
  4. Prepare in the order agents, resources, policy model, and wait for each to report prepared before starting the next; never pause an auxiliary model instance.
  5. On an agent deadline, retire the specific executions between boundaries (which requires the status route), abort the same attempts at the model server, then re-prepare; on any other prepare failure, decide between retry and abort, and on abort call resume on every participant already prepared. Re-dispatch every sacrificed rollout at attempt N+1, never N.
  6. Commit only after every participant is prepared; take the TransferQueue cut after the model drain reports zero in flight and finalizers are idle; publish only after every commit returned a manifest digest.
  7. Restore into fresh processes with empty capture directories, in the order model, resources, agents; reconcile custody manifests against restored staging rows and boundary revisions against session revisions before selecting any continuation; downgrade any mismatch to a fresh dispatch.
  8. Resume in the order resources, model, agents; only then dispatch continuations and fresh work.
  9. Issue /run with no total timeout and treat duplicate_execution as "still running"; keep a live-execution registry so a result that outlives its socket is not lost.

Test coverage

The stack's tests are thorough within each participant: the atomic close-versus-admit race is run a hundred times, manifest-last ordering and digest validation are exercised for every writer, parked runs survive cancellation, commit retries return the original result, and a real two-worker uvicorn pool is driven through the coordinator.

There is no SimpleAgent boundary or continuation test at all, and the Gymnasium continuation test calls run directly, bypassing the /run wrapper, so it never exercises admission, begin, or the resources mapping; a nonterminal continued step in that test would fail with "no active /run".

One coordinator test aborts with a transport id (7-1-a2 at attempt 2) rather than the logical id, which would fence the wrong ledger file in production; the tests encode a contract the code does not have.

No test drives a checkpoint across participants. The sequences that have no coverage are the ones the edge cases above come from: an agent parking while the model is paused; resources prepare during an agent's tool calls; a restart followed by a continuation through the real /run wrapper with the resources mapping; two participants of one kind committing into one directory; a second checkpoint after a restore; any resources adapter round trip through the real app with cookies and the JSON hop; the composition of the session and context middlewares; a verify in flight during prepare; the lineage of a continuation's first policy call; header-less callers on a checkpoint-enabled resources server; and any run past a few hundred executions.

Suggested fix order

  1. Cross-attempt lineage and the tombstone split (E10, E11), because every continuation that ships without them trains on truncated policy output silently, and the second checkpoint after any restore drops the custody the first one saved. This decides the model-server and agent contract for the first post-restore call.
  2. Per-instance checkpoint directories (E31), because any run with two agent servers loses one server's checkpoint today.
  3. Status routes, park-now handling, and the agent state machine (E4, E5, E19, E20), because without them the deadline policy cannot be applied, the safe prepare order cannot be verified, and an abandoned checkpoint leaves runs hanging.
  4. Resources participant robustness (E22, E23, E25, E26, E27, E28), because today a single failed seed poisons every later checkpoint, MCP traffic is refused, and most Gymnasium environments advertise an export that fails.
  5. Role default and capability accuracy (E6, E7, E38), so the actor's capability check means what it says.
  6. Reconciliation contracts (E12, E16, E24) specified precisely enough for the RL-side implementation, with the manifest route keyed so a continued rollout resolves under both capture keys.
  7. Bookkeeping release and the shard writer (E18, E41, E42) before any run at the intended scale.
  8. Restore failure recovery and status phases (E32, E33), so an operator has a route out of every paused state.
  9. Coordinator phase alignment and hardening (E35, E36) before multi-worker startup is wired.
