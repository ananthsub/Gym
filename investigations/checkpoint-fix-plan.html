Partial-rollout checkpointing · follow-up to the stack review

Checkpoint Fix Plan

Fixes the 42 cases in the stack review Extends continuation to blackbox harnesses Stack NeMo Gym PRs 2939–2946 Date 2 September 2026

The 42 cases are not 42 fixes. They collapse into nine workstreams, and three of those decide the shape of everything else: parent resolution across attempts of one rollout, a park-now protocol that every caller of a paused server obeys, and per-instance checkpoint namespaces with release of bookkeeping. Most of the remaining cases are one-line to one-function corrections inside the participants the stack already has.

Blackbox harnesses do not need a sandbox to pause and resume. They need two things the stack does not yet provide: a model server that holds a refused call instead of failing it, which gives an opaque harness a clean turn boundary without its cooperation, and a per-rollout home for the harness's own session store and working directory that survives the checkpoint. With those, Claude Code, Codex and OpenCode resume through their own session mechanisms after a restart, and after a same-process checkpoint they never notice anything happened. A sandbox becomes necessary only for the last tier, freezing a process tree mid-call, which none of the current providers can do and which this plan defers.

The workstreams

W1 Identity and lineage across attempts blocker

Closes E1, E2, E10, E11, E14, E15, E16. Lands in PRs 2939 and 2941.

  • Resolve parents across the attempts of one rollout. In resolve_parent, when the lineage store returns unresolved and the context's attempt index is above zero, retry the resolution against the earlier capture keys of the same logical rollout, from rollout_id-a{N-1} down to rollout_id. A fingerprint match there admits a token_in child whose staging_chain continues the parent's, exactly as within one key. Only when every attempt is exhausted does the existing rule apply: poison the call unless the rollout has no rows anywhere. The keys to search come from the restored manifest's source attempts, so the model server never guesses.

    This is one lookup loop in FileLineageStore plus a change in resolve_parent's fallback. It serves whitebox agents, which resend the restored output items, and blackbox harnesses, which resend their own transcript; both produce the same fingerprints. An optional hint header from the agent, x-nemo-gym-parent-call-id with the parent's capture key, can short-circuit the search but must still be verified by fingerprint, so implement the search first.

  • Separate admission tombstones from commit exclusions. A tombstone fences new calls under a retired attempt; it must never hide that attempt's already-committed rows. Keep two sets in the limiter: tombstones for admission, and excluded_at_checkpoint holding only attempts force-closed by abort_inflight during the current checkpoint. Commit excludes the second set and clears it on resume; restore installs tombstones from the manifest's tombstone list and its source attempts without ever adding them to the exclusion set. The second checkpoint after a restore then commits the restored ledgers again.

  • Make restore idempotent on the same namespace. Accept a capture directory whose existing ledger files are all named in the manifest with matching digests, and refuse only files the manifest does not know. A same-node restart with the same directory then restores cleanly, and a retried restore is a no-op.

  • Fence identity at dispatch. Reject an explicit rollout id that matches -a\d+$ with its own error code, and reject a dispatch at attempt zero for a rollout that the restored manifest lists as a source attempt with a code that says "id reused across restart" rather than "stale attempt". NeMo RL passes an explicit, job-unique _ng_rollout_id in every dispatch.

  • Echo the model-call id whenever admission identity exists. Mint and return x-nemo-gym-model-call-id for header-identified calls, not only for capture-prefixed ones, so a boundary always carries the id that a later reconciliation needs.

W2 Park-now and the prepare protocol blocker

Closes E4, E5, E9, E17, E39. Lands in PRs 2940, 2942, 2943, 2944, 2945.

  • Every refusal a paused server issues is a park signal, not an error. Define one rule for the three checkpoint codes, checkpoint_parked, resources_admission_closed and agent_admission_closed: a whitebox agent that receives one re-commits its last boundary through park_now() and blocks until resume, then reissues the refused operation. The refused response never enters the conversation: the tool-call path in SimpleAgent checks the checkpoint codes before treating a body as tool output. With this rule the prepare order stops being a correctness requirement and becomes a latency preference.

  • Hold instead of refuse for callers that cannot park. The admission limiter distinguishes a caller with identity headers, which understands the codes, from a path-identified caller with none, which is an SDK inside a harness. The second kind is held: the request waits on the limiter's resume event up to a configured hold budget and is counted as a waiter, not as in flight, so it cannot block the drain. Past the budget it receives HTTP 503 with retry-after. Held waiters appear in status per rollout, which is the signal the blackbox tier below builds on.

  • Add status routes to the agent and resources participants. GET agent-checkpoint/status returns each active execution with its rollout, attempt, state, boundary index, current operation and age; GET resources-checkpoint/status returns each registered session with its lock state and revision. Both accept the same long-poll parameters as the model status. The prepare-incomplete error lists the blocking attempts so the deadline policy can retire exactly those.

  • Count what prepare lost. Prepare's report includes executions that failed after park was requested, and the actor treats a nonzero count as a sacrifice to record, not as success.

  • Add resources-checkpoint/retire. It drops the session, mapping, revision and lock for one attempt, and the actor calls it for every sacrificed attempt before resources prepare so no orphan session is exported.

  • Fix the judge fail-safe for control refusals. When the judge error is a checkpoint code, the fail-safe returns HTTP 503 with the code rather than a successful zero reward, so the resources middleware does not retire the session and the agent parks instead of finishing.

  • State the order anyway. Agents, then resources, then policy model; resume in reverse. The actor enforces it; Gym documents it in the control-plane docstring and the design page.

W3 Agent execution state machine serious

Closes E19, E20, E21, E18, E8. Lands in PRs 2942, 2943, 2944.

  • Cancel the task that is parked, not the task that began. commit_boundary records asyncio.current_task() on the execution at the moment it parks, and retire cancels that task as well as the outer one. Better still, SimpleAgent's inner self-call inherits a per-execution cancel scope so both handlers fall together.

  • Generation-stamp executions. Each execution carries a generation counter; begin under a retired key increments it and commit_boundary from a stale generation is refused with a distinct code. A zombie loop can no longer write into its successor's record.

  • Undo park requests when a checkpoint is abandoned. A failed prepare resets park-requested executions to running before returning its error. Resume resets any remaining park-requested execution to running and releases or cancels task-less parked ones, so nothing waits for a resume that will never come.

  • Never commit a boundary at the step budget. Both agents skip the boundary when the step equals max_steps; a continuation whose boundary index already meets the budget returns the truncated response from the restored items without a model call.

  • Release completed executions. Drop an execution's boundary payload on finish and drop the execution itself when the actor acknowledges the result (the ack route in W7); drop a restored continuation once its /run has begun.

  • Refuse a fresh dispatch that shadows a continuation. If an unconsumed restored boundary exists for a rollout, a /run at any other attempt is refused with a code naming the expected attempt.

W4 Resources participant robustness blocker

Closes E22 through E30. Lands in PRs 2945 and 2946.

  • Install the session middleware inside the context middleware and classify by route. Reading identity from the context variables lets a capture-prefixed path and a header-only path resolve the same way, and the literal /verify comparison sees the stripped path. Only POST routes that a server declares as mutations are gated; GET /, docs and metrics pass.

  • Give MCP calls an identity. At /seed_session, mint the rollout id and attempt into the signed MCP session token; the MCP dispatcher validates the token and enters the same per-attempt lock and revision accounting as a direct tool call. This is the single change that makes stateful environments usable by sandboxed harnesses under checkpointing.

  • Register after success, export defensively. The middleware registers an attempt only on its first successful response, and the export loop skips keys the adapter cannot map, reporting them in the prepare result instead of raising. After taking each lock, prepare re-reads the registry and skips keys retired meanwhile, and reads the revision under the lock rather than from the pre-materialized list.

  • Count revisions only on mutations. Adapters declare their mutation routes (the default is every declared POST tool route plus /reset and /step); reads and /seed_session do not bump the revision.

  • Start paused when a restore is expected. A launcher flag or the presence of a configured restore directory starts the participant with admission closed, so no attempt above zero can mutate a cookie session before restore installs the mapping.

  • Make Gymnasium opt in. GymnasiumServer.checkpoint_state_enabled returns true only when the subclass overrides the serialization hooks; Blackjack opts in, Sokoban, Tetris, TALES, the multi-turn example and OpenAir report stateless until they implement their own codecs.

  • Normalize on restore. Workplace Assistant converts NaN back to None and resets frame indexes; the adapter tests add the JSON hop.

  • Prune on retire and on same-process restore. Retire pops the lock when it is not held; restore retires the source attempt it tombstones.

W5 Roles, capabilities, and configuration serious

Closes E6, E7, E38. Lands in PRs 2940 and 2941.

  • Default the model role to auxiliary. The training config marks the single instance NeMo RL generates through as policy; startup validation fails when a run declares more than one policy instance or none. Judges and simulators stop pausing by omission.

  • Make the agent capability truthful. checkpoint_mode becomes a class-level declaration: SimpleAgent and GymnasiumAgent declare export_restore, the base declares stateless, and a blackbox agent moves to export_restore only when the blackbox tier below lands for it. Prepare on a stateless agent returns immediately with its executions listed for retirement or hold.

  • One bearer, one name. Collapse the two environment variables into NEMO_GYM_CHECKPOINT_CONTROL_TOKEN, log the resolved source at startup, and have the actor assert each participant's expected capability before the first checkpoint.

W6 Control-plane consistency serious

Closes E13, E32, E33, E34, E35, E36, E37, E40. Lands in PRs 2940 and 2941.

  • Close admission after validation, not before. The model restore validates the checkpoint directory first and closes admission only when it is about to install; a failed restore leaves the server accepting. Model resume is additionally allowed from idle when the limiter is closed, so any stuck state has an exit.

  • Align the coordinator with the single-worker routes. Abort and resume accept the preparing phase; status accepts every non-idle phase; the status request model is shared so both deployments take the same parameters; the coordinator's resume rolls back to draining if acknowledgements fail.

  • Let commit promote the phase. A commit whose own quiescence check passes promotes preparing to prepared instead of demanding a prior status poll.

  • Refuse checkpoint routes without a coordinator. When num_workers exceeds one and no coordinator is attached, the routes answer with multi_process_unmanaged rather than acting on one worker.

  • Give every admitted request an abort handle. abort_inflight accepts a ticket id, and status lists tickets, so an identity-less generation can still be sacrificed at the deadline.

  • Turn a cancelled admitted call into a clean refusal. The capture middleware converts a cancellation after admission into HTTP 409 stale_attempt, and the manifest reader treats a failure row for an already-recorded id as poison.

  • Carry both an absolute deadline and a relative budget, use the smaller, thread the deadline through abort, resume and status, and return the server's clock in every control response so the actor can detect skew.

  • Rewrite the manifest on a commit retry when the exclusion set changed.

W7 Checkpoint layout and bookkeeping release serious

Closes E31, E41, E42, E18. Lands as one new PR after 2941, consumed by 2942 and 2945.

  • Namespace every participant by instance. Commit and restore write under <checkpoint_dir>/<component>/<server_name>/ for agents and model servers as the resources participant already does, and the manifest records the server name so a mismatch is refused.

  • One shared checkpoint writer. A CheckpointArchiveWriter streams records into compressed shards with a member index of rollout to shard, offset and length, writes each shard through a temporary name with fsync and rename, and returns a digest. All three participants serialize their records through it; the manifest-last discipline and digest verification carry over. Restore reads the index and extracts only what it installs.

  • Commit incrementally. The model manifest records the highest committed row offset per capture key; the next commit copies only new or grown files, and the archive index chains to the previous checkpoint's shards by digest.

  • An ack route for release. POST /ng-control/v1/ack {rollout_id, attempt_index} on every participant lets the actor say a rollout's result is durable on the RL side. On ack the agent drops the execution, the model retires the attempt from the seen set and, once no later attempt exists, from the tombstone set, the resources server drops locks and any leftover session, and the coordinator sends tombstone deltas instead of the full list.

W8 Actor-side reconciliation contract serious

Closes E12, E24, E16. Lands in NeMo RL.

  • Per logical rollout, join the manifests of every capture key from the restored source attempts, verify each row's staging key exists in the restored TransferQueue with a matching digest, and downgrade the rollout to fresh dispatch on any miss.

  • Cut the chain at the boundary. A continuation is runnable only if its boundary's last_committed_model_call_id is present and verified; rows after it under the old attempt are ignored, which handles late calls from a zombie.

  • Compare revisions per resources server between the boundary and the snapshot; a mismatch downgrades the rollout.

  • Dispatch continuations at exactly source plus one, and never retry /run with the same attempt; treat duplicate_execution as still running and wait for the ack path.

W9 Cross-participant tests serious

Lands beside each workstream; the harness lands with W2.

  • Extend the staged data-plane simulation from the prototype branch into a four-participant harness: SimpleAgent, a stateful resources server, the policy model with the fake external staging store, and a test-side actor that runs prepare, commit, restart, restore, reconcile and resume. Every sequence the review found untested becomes one test on this harness: park under each prepare order, a tool call refused mid-turn, a boundary at the step budget, a retired execution's zombie, a restart continuation through the real /run wrapper with a resources mapping, header-less callers, and two agent servers committing into one directory.

  • A contract test drives the same control script against the single-worker model routes and the coordinator, so the two implementations cannot drift again.

  • A scale test with ten thousand synthetic executions measures commit and restore time and process memory before and after the ack route and the archive writer.

Blackbox harnesses

How Claude Code runs in Gym today

The Claude Code agent starts claude -p --output-format stream-json as a local subprocess of the agent server. There is no sandbox; the agent records the gap no_sandbox_runtime in its observations. Each request gets a fresh CLAUDE_CONFIG_DIR that is deleted when the run ends, and the working directory is the agent server's own. The model server is reached through ANTHROPIC_BASE_URL, which carries the capture prefix, so identity and token capture already work for every call the harness makes. Tools reach the resources server over MCP with a session token minted at seed time. A configured timeout kills the process, and the run is one shot: instruction in, transcript out, then /verify.

Codex runs the same way with a per-run CODEX_HOME. OpenCode, anyswe, anyterminal and the other sandboxed agents run their harness inside a sandbox created through the sandbox API. The nine providers implement create, exec, file transfer, status and close; some add endpoints and terminals, and some can reconnect to a live sandbox by id. None can snapshot a filesystem or freeze a process.

Three tiers of continuation

The question "can a blackbox harness pause and resume" has three answers with increasing cost, and the middle one is the useful one.

Tier 0 — restart only, what the stack does today by accident

needs: hold-first admission (W2), retire, tombstones

At prepare the actor retires the execution, the agent kills the harness, and after restore the rollout is dispatched again from its input under a new attempt. The tokens generated by the abandoned attempt stay in TransferQueue as masked orphans. Nothing about the harness is persisted. This is correct and cheap; its only cost is the lost work of every blackbox rollout in flight at each checkpoint, which at ten-minute checkpoint intervals and hour-long coding tasks is most of them.

Tier 1 — harness-native resume at a turn boundary

needs: hold-first admission, per-rollout harness home and workspace, cross-attempt lineage (W1), MCP identity (W4)

Claude Code, Codex and OpenCode all persist their own conversation state between turns and can continue a session non-interactively: Claude Code with --resume <session-id> against the transcript it keeps under its config directory, Codex through its session store under CODEX_HOME, OpenCode through the session database the agent already reads. The problem was never persistence; it was finding a moment when the harness is between turns and knowing that it is.

Hold-first admission supplies that moment. When the policy model pauses, the harness's next API call is held rather than refused. At that instant the harness is idle at a turn boundary by construction: its transcript contains every completed message and every tool result, and its only pending action is the held request. The model server's status reports the held waiter under the rollout's identity, and the agent participant treats "held at the model" as the blackbox equivalent of a committed boundary. The agent then snapshots the harness's home directory and workspace, records the session id it already parses from the stream, and commits that as the boundary. On a same-process checkpoint nothing more happens: resume releases the held request and the harness continues without ever knowing. On a restart the agent restores the two directories at the same paths, relaunches the harness in resume mode, and the harness reissues the request it was holding. That request resends the full transcript, which W1's cross-attempt resolution matches to the previous attempt's last call, so the token chain continues as token_in rather than restarting as a re-tokenized root.

The abandoned held request needs no relay: it was never admitted, so no custody row exists and no staged row is orphaned. The only reissue case is a request that was admitted and mid-generation when the deadline forced an abort; that attempt is tombstoned as today and the harness's reissued call after resume is a fresh child of the last committed parent.

Tier 2 — full runtime snapshot

needs: a provider that can freeze and restore a process tree, the egress relay, endpoint and attempt remapping

Freezing the harness mid-call and thawing it later requires a sandbox whose provider can checkpoint process memory, an in-runtime relay that owns every socket the harness has open so a frozen request can be captured and reissued, and a remap of the model endpoint and attempt identity at thaw. No current provider offers the first, and tier 1 covers every harness Gym ships today. This plan defers tier 2 to the harnesses that cannot resume natively, if any appear.

Hold-first admission, precisely

  • Classification. A gated request with identity headers is a parkable caller and receives HTTP 409 checkpoint_parked as today. A gated request identified only by its capture path is a holdable caller.

  • Holding. A holdable request registers a waiter keyed by its identity and awaits the limiter's resume event with a timeout equal to the hold budget. Waiters are reported in status but never counted in flight, so they cannot delay the drain and never need aborting. On resume the waiter is admitted in place and proceeds normally. Past the budget it receives HTTP 503 with retry-after, which every SDK retries.

  • Budget. The budget must stay below the SDK's own request timeout, which is ten minutes for the Anthropic and OpenAI clients by default, and below the harness's per-request timeout if it sets one. Retry behavior on the client side is not something to rely on: the SDKs retry a refused call only twice by default and the CLIs add short loops of their own, so holding on the server is the only mechanism that spans a checkpoint of several minutes.

  • Restart. A held request whose server process exits sees a connection reset; the harness's retry loop reissues it against a server that is gone, and the harness eventually fails. That is why the tier-1 snapshot happens while the request is held and why the harness is killed by the agent after the snapshot rather than left to time out.

Is a sandbox required to pause and resume?

No, for tiers 0 and 1. The harness's continuation state is filesystem state: its own session store and the working directory it edits. What tier 1 needs is that both live in a per-rollout location that survives the checkpoint and is restored at the same absolute path, because the CLIs key their session stores by working directory. For a local subprocess, the agent server owns those directories directly and includes them in the checkpoint through the archive writer of W7; the workspace can be large, so the writer content-addresses files against the task's base image or repository and stores only the delta. Today's per-request temporary config directory and shared working directory must become per-rollout directories with a lifecycle tied to the execution, which is the concrete change to the Claude Code and Codex agents.

A sandbox changes the cost, not the possibility. With a provider that can reconnect to a live sandbox by id, the sandbox itself outlives the agent server's restart: the boundary stores the serialized handle, restore reconnects, and nothing is copied. That is the existing ConnectableProvider protocol doing exactly what it was built for, and the sandboxed harnesses gain a cheaper tier 1 than the local ones. Without reconnection, the agent must download the two directories from the sandbox before killing it and upload them into a new one, which the provider protocol already supports through file transfer.

Yes, for tier 2. Freezing a process mid-request is a provider capability, and it needs the egress relay to own the harness's sockets. No provider in the repository has it. Tier 2 is the fallback for a harness with no native resume, not the path for Claude Code.

What Claude Code specifically needs

  1. Pin the session id. Launch with --session-id <uuid> derived from the rollout and attempt, or read it from the first stream event as the parser already does, and record it in the boundary.
  2. Per-rollout home and workspace. Replace the per-request temporary CLAUDE_CONFIG_DIR with a directory keyed by rollout that persists until the execution is acknowledged; give each rollout its own working directory at a path the restore can reproduce. The skills staging and MCP config file move into that home.
  3. Boundary detection. The agent participant polls the model server's status for a held waiter under the execution's identity, or receives it as a push from the limiter when both run in one deployment, and treats it as the park signal. A harness that is executing a tool when prepare arrives reaches the hold at its next API call, which is the same behavior as a whitebox agent finishing its turn.
  4. Resume launch. After restore, relaunch with --resume <session-id> in the restored home and workspace, the same instruction context, and the base URL carrying attempt N+1's capture prefix. Claude Code continues from the last completed message and reissues the pending request itself.
  5. Identity for tools. The MCP session token minted at seed time carries the rollout and attempt (W4), so the resumed harness's tool calls reach the restored resources session under attempt N+1 without any change to the harness.
  6. Lineage. The reissued request's transcript fingerprints to the previous attempt's last committed call under W1, so the training row continues as a token-in chain. Without W1 a resumed Claude Code run is trainable but only on the tokens it generates after the restart.
  7. Capability. The agent declares checkpoint_mode: export_restore only once steps 1 to 4 are implemented; until then it declares stateless and prepare retires its executions immediately.
Codex follows the same seven steps with CODEX_HOME as the home directory and its session resume command as the relaunch. OpenCode already exposes the session database the agent reads for observations, and its resume path is its session flag. Harnesses that run inside a sandbox add one step: serialize the sandbox handle into the boundary when the provider can reconnect, otherwise transfer the two directories out before the kill.

Landing the changes in the stack

  1. PR 2939 (identity): dispatch-time id fencing and the reused-id error code from W1; the single bearer name from W5.
  2. PR 2940 (control contracts): hold-first classification and waiters in the limiter, shared status request model, coordinator phase alignment, ticket-id abort, deadline and clock fields, refusal when unmanaged, from W2 and W6.
  3. PR 2941 (model participant): cross-attempt parent resolution, the split between tombstones and exclusions, idempotent restore, close-after-validation, model-call id on header-identified calls, cancellation to a clean refusal, auxiliary default with startup validation, from W1, W5 and W6.
  4. New PR after 2941 (checkpoint writer and ack): per-instance namespaces, the archive writer, incremental model commits, the ack route and bookkeeping release, from W7.
  5. PR 2942 (agent participant): park-now, status route, prepare-loss counting, parked-task cancellation, generation stamps, park-request rollback on failure and resume, continuation shadow refusal, class-level capability, from W2, W3 and W5.
  6. PRs 2943 and 2944 (SimpleAgent, Gymnasium): checkpoint codes never enter the conversation, the step-budget boundary rule, and the parent hint header once W1 supports it.
  7. PR 2945 (resources participant): middleware placement and route classification, register-after-success, defensive export, lock-ordered revisions, retire route, start-paused flag, judge fail-safe change, from W2 and W4.
  8. PR 2946 (adapters): Gymnasium opt-in, MCP identity in the session token, Workplace normalization, mutation-route declarations, adapter tests with the JSON hop.
  9. New PR (blackbox tier 1): per-rollout home and workspace for Claude Code and Codex, held-waiter boundary detection, resume-mode relaunch, and the boundary schema for harness state; the sandboxed agents add handle serialization.
  10. NeMo RL: W8's reconciliation, the prepare and resume order, sacrifice as retire plus abort, unique ids, and the ack calls.
